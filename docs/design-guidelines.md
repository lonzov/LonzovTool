# 设计细则

`AGENTS.md` 设计规范 6–8 的执行细节：正文只留原则，判据、栅格与自检清单放这里。

## 一、选型：先形态，后组件

组件库保证“用法正确”，这里保证“选择正确”。按「任务形态 → 信息结构 → 按交互语义选组件 → 布局实现」推进，不跳步；接口用对但组件选错、层级错，仍判不合格。

项目现成的四类形态，新增形态前先答“为什么不用这四个”：

| 形态 | 承载什么 | 现有实现 |
| --- | --- | --- |
| 区域容器 | 一组内容或一个功能区，内部再分组 | `ConsolePanel`、`RawJsonCard`、`tool-card` |
| 卡片 | 一条可独立识别的实体，图文混排、发现式浏览 | `ToolCard` |
| 行列表 | 同质、可扫读比较、操作统一的条目 | 控制台的 `data-row` 行 |
| 浮层 | 短促打断任务用 `AppModal`；需保留上下文的详情与编辑用抽屉 | `AppModal`、`FeedbackDrawer` 等 |

判据：

- 用户是在扫一批，还是在看每一个？扫一批用行列表，看每一个用卡片。
- 单主信息 + 少量元信息用行列表；多字段需要对齐比较才考虑表格式对齐。本项目目前没有表格组件，需要时先在本文件登记形态，不要临时用行拼一个。
- 卡片装“一条内容”，区域容器装“一组内容”。卡片是区域的地毯，不是元素的包装盒。
- 属性分类用标签，状态计数用徽标，动作才用按钮；不可点的状态不得做成按钮样。
- 单个数字、一行文字、一个按钮不单独包容器。

反例：20 条同质记录做成 20 张卡片流——应当是一个行列表，行内统一操作。

## 二、容器层级

- 页面底 → 区域容器 → 内容。区域容器内部用标题、留白、分隔线分组，不再给子组套小卡片。
- 有底色、边框或阴影的实体容器嵌套不超过 2 层。`AppModal` / 抽屉内部的面包算第 2 层，其内部只允许用标题、留白、分隔线分组。
- 容器比内容安静：容器的底色与描边视觉权重必须低于内容，不允许比内容更抢眼。
- 拥挤即错误，出现任一信号就回第 2 步重排，不得用缩字号、压内边距、加局部滚动来“塞下”：
  - 相邻两层都有边框或底色；
  - 小容器自带滚动条；
  - 内容边界靠猜；
  - 一个区域内出现两套以上间距梯度。
- 内边距不得低于组件默认。既有密集形态（工具编辑区、控制台行）除外，新页面不得以压缩内边距换取容纳量。

## 三、味道测试

动手前自问，不是验收项：

- 这一屏放进 Linear、Notion 这类信息产品里违和吗？违和必须指认具体一处——对齐、间距、层级还是密度。指不出具体位置，说明是在敷衍自己。
- 每个容器回答它存在的理由：分区、分组，还是习惯性包了一层。答不上来的删掉。
- 工具编辑区允许比 Linear 更密：那是专业工具，不是内容产品，密度本身就是它的价值。

## 四、布局与栅格

### 页面骨架

内容区一个宽度，`margin-inline: auto` 居中，页面左右留白 20–24px（窄屏 16px）。子区域不再自设 `max-width`，一屏内不允许出现第二套宽度体系。

### 场景宽度

一处一个值。新增场景先在这里登记，再写页面：

| 场景 | 宽度 | 说明 |
| --- | --- | --- |
| 默认页面（首页、设置、控制台、工具页） | 1200px | 全站基准 |
| 表单、提交类 | 760px | 单列表单，过宽会散 |
| 文档阅读（Markdown） | 待定，现 640px | 计划压到更适合阅读的行宽，调整后更新本表 |
| 落地页（关于页） | 1240px | 独立设计，不参与全站体系，属已批准例外 |

### 列与栅格

- 列宽一律 `repeat(auto-fit, minmax(X, 1fr))`，X 按内容取：指标 140、卡片与工具格 200、面板与分栏 320。
- 数量不定、需要撑满用 `auto-fit`；需要保持卡片宽度、避免横向拉伸用 `auto-fill`。
- 不写死列数，不用百分比凑宽度。固定两栏只在“字段对字段”这类稳定结构上用。

### 断点

- 只允许三档，且只用于结构塌缩：≤640 单列 + 工具栏换行；≤768 页面级双栏塌成单栏；≤1100 控制台侧栏让位。
- 480 只用于表单内部（双列字段塌成单列），不作页面级断点。
- 字号与内外边距不随断点改，用 `clamp()` 与 `auto-fit` 自适应。
- 存量代码里有二十来种断点取值，新代码只用上面这些；旧代码随改动迁移，不为统一而专门重构。

### 密度

控件高度、行高、内边距由组件 size token 决定，页面不自己调。页面只决定“一行放几样东西”。

## 五、80% 交付自检

把窗口缩到 80% 后逐条过，能实测就实测，不能实测按数值推算并说明未实测。

文字：

- 正文不小于 14px，关键信息不落在辅助层级。
- 标题按下面三级取值，不得低于 14px：

| 层级 | 字号 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面标题 | 22px（窄屏 19–20px） | 600 | 页面头部 |
| 区域 / 弹窗标题 | 15–16px | 500–600 | 面板、Modal、卡片标题 |
| 字段标签 | 13–14px | 500–600 | 表单标签、行内小标题 |

- 12–13px 只能做标签与元信息，不得承担标题职责；标签与同级标题不得同字号。
- 层级靠字号与留白建立，不靠加粗：相邻两级至少有两项不同（字号、字重、留白、颜色），只改字重不算分层。一个界面内的标题层级不超过三级。
- 标题用 `--foreground`，不得用 `--muted-foreground` 或更低的明度做标题色。
- 字重上限 600，界面里不用 700 以上（落地页、海报这类独立设计除外）。600 只允许用在 `--foreground` 的文字上，`--muted-foreground`、`--subtle-foreground`、`--disabled-foreground` 一律 500 及以下；也不得为了能用 600 而把文字提到 `--foreground`——层级由信息重要性决定，不由字重决定。
- 中文不加负字距；只有 ≥20px 的大字才允许 -0.01 ~ -0.02em 收紧。标题行高 1.3–1.4，与正文行高拉开。
- 中文在 ≤12px 时不用 ≥600 字重，笔画会糊。
- 截断必须有 tooltip 或展开，不得丢掉关键信息。

小字号、粗字重、低对比、紧字距四项叠加，结果是“加粗的说明文字”而不是标题。判断方法：标题若必须与正文比粗细才能分辨，即不合格。

对比度：

- 正文 ≥4.5:1，辅助信息 ≥3:1，以 `/dev/palette` 的对比度矩阵实测为准。
- 不得用 `--subtle-foreground` 表达禁用或不可点，那是低对比伪装成层级。

层级与状态：

- 层级只用明度阶（`--foreground` → `--muted-foreground` → `--subtle-foreground` → `--disabled-foreground`），不新造灰阶，不用色相分主次。
- 状态不能只有颜色一个通道，须再给文案、图标或形状之一。
- 主操作 3 秒内可定位；键盘 focus 可见。

布局：

- 无意外横向滚动、无重叠遮挡、无内容挤成团。
- 间距沿用相邻区块的梯度，一个区域内不超过三档。
- 区块关系不读文字也能看出哪里是一组、哪里是分区。

不达标视为未完成。修复顺序：结构与选型 → 布局 → 最后才动主题配置；禁止缩小内容或压缩留白去迁就错误结构。

## 六、偏离与例外

- 技术性覆盖（`!important`、`:deep`、自造组件）：在代码里写明缺的是哪条 token 或变体。只写约束本身，不写规则条款号，也不写“按要求”。
- 纯视觉偏离（营销页、海报、落地页）：登记在下表，不进代码。

| 位置 | 偏离 | 原因 |
| --- | --- | --- |
| 关于页 | 内容宽度 1240px，整体按落地页设计 | 纯展示页，信息密度与工具类页面不同 |
